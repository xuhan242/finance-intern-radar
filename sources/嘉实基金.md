## 接口

```
POST https://app.mokahr.com/api/outer/ats-apply/website/jobs/v2
Content-Type: application/json
Origin:  https://app.mokahr.com
```

请求体：

```json
{
  "orgId": "jsfund",
  "siteId": 44330,
  "locale": "zh-CN",
  "limit": 50,
  "offset": 0
}
```

认证要求：无。不需要登录、cookie、签名或 Referer 校验。`limit` 实测上限 **50**（传 100 时返回 `success=false, code=102`），配合 `offset` 以 50 为步长分页。（2026-10-08 夜间复核修正：早前记录的"limit 100 可用"不成立。）

响应加密：返回体为 `{"data": "<base64 密文>", "necromancer": "<16 字节密钥>"}`。密文为 AES-128-CBC，IV 为全局常量 `de7c21ed8d6f50fe`，密钥取响应中的 `necromancer` 字段，明文随响应一并下发。解密后结构为 `{code, codeType, data: {jobStats, jobs}, msg, success}`。

`jobStats.total` 恒为 0，不可用于计数。

## 字段映射

| 目标字段 | 接口字段 | 说明 |
|---|---|---|
| 岗位名 | `title` | 日常实习岗以"日常实习-"开头 |
| 部门 | `department.name` | 混合填法人主体与部门，如"嘉实基金管理有限公司""基金运营部" |
| 岗位性质 | `commitment` | 值域 `实习` / `全职`，但**数据脏，不可直接采信** |
| 发布时间 | `publishedAt` | ISO 8601 |
| 备用时间 | `createdAt` / `updatedAt` / `openedAt` | |
| 在招状态 | `status` | `open` |
| 唯一 ID | `id` | UUID |

不落盘字段：接口未返回 JD 全文，无需额外排除。

**时间基准字段：** `publishedAt` —— 用于时间窗口判定与结果排序。

## 实习性质识别

`commitment` 字段不可作为唯一判据：日常实习站 9 条在招岗位中有 4 条被标为 `全职`，例如"日常实习-养老金另类投资实习生""日常实习-产品研究助理"，属出租方录入错误。

可靠判据是**岗位名前缀"日常实习-"**。

## 已知缺项

列表接口不返回城市。返回字段中无 `locations`，城市仅能从岗位名中提取（如"日常实习-机构销售实习生（base北京）"）。门户页面存在"工作地点"筛选项，说明数据存在于详情层，如需城市字段须另行探测详情接口。

## 合规备注

招聘页为 Moka 托管，接口响应经 AES-128-CBC 加密，密钥随响应明文下发。判断：该接口无登录墙、无验证码、无签名校验，密钥与密文同源下发，不存在被绕过的访问控制，性质等同 zip/base64 这类前端编码，不构成"避开或破坏技术管理措施"。此判断经用户确认后取数。

待留意的代价：需要 AES 解密依赖（Python 侧为 `pycryptodome`）；Moka 若调整加密方案，解析会连带失效，稳健性弱于北森系。
